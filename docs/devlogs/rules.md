# Sui MEV Bot - 开发规则与最佳实践

## 技术栈规则

### 核心技术栈
- **语言**: Rust (稳定版本)
- **区块链**: Sui Network
- **异步运行时**: Tokio
- **序列化**: serde, bcs, bincode
- **网络**: reqwest, tokio-tungstenite
- **并发**: rayon, async-channel

### 依赖管理规则
1. **Sui依赖**: 统一使用`suiflow/mevsui`分支的`relay-patch`版本
2. **版本锁定**: 关键依赖必须锁定具体版本或commit hash
3. **工作空间**: 使用workspace管理多个crate，避免依赖冲突
4. **特性控制**: 只启用必要的feature，减少编译时间

## 架构设计规则

### 模块化原则
1. **单一职责**: 每个模块只负责一个核心功能
2. **接口抽象**: 使用trait定义核心接口（如`Dex`, `Simulator`, `Collector`）
3. **依赖注入**: 通过构造函数注入依赖，便于测试和替换
4. **错误处理**: 统一使用`eyre::Result`进行错误处理

### 性能优化规则
1. **对象池**: 使用`ObjectPool`管理昂贵的资源（如Simulator）
2. **并发处理**: 使用`JoinSet`进行并发任务管理
3. **缓存策略**: 实现多层缓存（内存缓存、文件缓存）
4. **资源限制**: 设置合理的并发数量和资源上限

```rust
// 性能配置示例
const MAX_HOP_COUNT: usize = 2;        // 最大跳数
const MAX_POOL_COUNT: usize = 10;      // 最大池子数量
const MIN_LIQUIDITY: u128 = 1000;      // 最小流动性
const DEFAULT_WORKERS: usize = 8;       // 默认工作线程数
const DEFAULT_SIMULATORS: usize = 32;   // 默认模拟器数量
```

## 套利策略规则

### 风险控制
1. **最小利润**: 设置最小利润阈值，避免微利交易
2. **Gas费用**: 必须计算并扣除Gas费用
3. **滑点控制**: 考虑价格滑点对利润的影响
4. **流动性检查**: 只在高流动性池子中进行套利

### 执行优先级
1. **Shio交易**: 最高优先级（有deadline限制）
2. **私有交易**: 中等优先级（通过relay获取）
3. **公共交易**: 最低优先级（公开可见）

### 路径发现规则
```rust
// 路径发现限制
- 最大跳数: 2跳
- 路径去重: 避免使用相同的池子
- 流动性过滤: liquidity >= MIN_LIQUIDITY
- 池子数量限制: 每个token最多10个池子
```

## 数据处理规则

### 事件处理
1. **事件过滤**: 只处理swap相关事件
2. **错误容忍**: 单个事件处理失败不应影响整体流程
3. **重连机制**: 网络连接断开时自动重连
4. **背压处理**: 处理速度跟不上时的缓冲策略

### 数据存储
1. **本地优先**: 关键数据本地存储，减少网络依赖
2. **增量更新**: 只更新变化的数据，提高效率
3. **数据验证**: 存储前验证数据完整性
4. **备份策略**: 定期备份关键数据
